# bogema-landing

Лендинг БогемаТур: **Nuxt 4** (SSR) + **Directus 11** (CMS контента лендинга).

```
bogema-landing/
├── docker-compose.yml     Directus + Postgres (локально; порт 8055 / 5433)
├── .env.example           переменные compose (скопировать в .env)
├── directus/              схема как код + сиды + снимок схемы
│   ├── scripts/seed-schema.mjs    коллекции, поля, права публичной роли
│   ├── scripts/seed-content.mjs   демо-контент из прототипа
│   └── schema/snapshot.yaml       снимок схемы (pnpm directus:snapshot)
└── frontend/              Nuxt 4 (srcDir = app/)
    ├── app/pages/index.vue           главная = набор секций
    ├── app/components/sections/      HeroSection, PromoSection, ToursRail, …
    ├── app/components/ui/            TourCard, DestinationCard, ReviewCard, MediaSlot, Rail,
    │                                  StickyBar, Mascot, BusFrame, FavoriteButton
    ├── app/components/layout/        SiteHeader, SiteFooter
    ├── app/composables/              useDirectus, useLanding, useAssetUrl, useFavorites
    ├── app/plugins/reveal.ts          директива v-reveal (появление при скролле)
    ├── app/assets/css/motion.css      моушен-слой: токены, ревилы, полка, ховеры
    ├── app/assets/css/refine.css      доводка вёрстки поверх прототипа
    ├── app/types/schema.ts           типы коллекций Directus
    ├── app/data/mock.ts              моки = контент прототипа (фолбэк без Directus)
    ├── app/assets/css/               tokens.css + landing.css из прототипа, main.css
    ├── server/api/subscribe.post.ts  подписка → Directus (subscribers)
    ├── server/api/lead.post.ts       заявка   → Directus (leads)
    └── public/demo/                  демо-фото hero из прототипа
```

## Быстрый старт

```bash
pnpm install
cp .env.example .env               # поменять пароли/ключи
pnpm directus:up                   # http://localhost:8055  (admin@bogematur.ru / из .env)
pnpm directus:seed                 # коллекции + права
pnpm directus:seed:content         # демо-контент (только в пустые коллекции)
pnpm dev                           # http://localhost:3000
```

Без Directus фронт тоже поднимается: `useLanding()` при ошибке отдаёт моки.
Принудительно на моках: `NUXT_PUBLIC_USE_MOCK=true` в `frontend/.env`.
Бейдж «данные: моки» убран из макета — источник видно по `data.source`.

## Как устроены данные

Одна точка входа — `useLanding()` (`frontend/app/composables/useLanding.ts`).
Она за один SSR-проход тянет всё, что нужно главной, и отдаёт объект `LandingData`:

| Поле `LandingData` | Коллекция Directus | Секция |
|---|---|---|
| `settings` | `site_settings` (singleton) | шапка, футер |
| `landing` | `landing` (singleton) | SEO, заголовки секций, промо, тексты форм |
| `menu` | `menu_items` (`placement`) | шапка + 3 колонки футера |
| `heroSlides` | `hero_slides` | `HeroSection` |
| `excursions` / `tours` | `tours` (`kind` = excursion / tour) | два `ToursRail` |
| `destinations` | `destinations` | `DestinationsGrid` |
| `advantages` | `advantages` | `WhySection` |
| `reviews` | `reviews` (+ M2O `tour`) | `ReviewsSection` |

Картинки — поле-файл Directus, URL строит `useAssetUrl()` (`/assets/<id>?width=…&format=webp`).
Компонент `MediaSlot` рисует `<img>` либо заглушку `.slot-empty`, на которую завязаны
CSS-правила из прототипа (тёмная/светлая шапка, градиенты карточек).

## Моушен

Всё движение собрано в `app/assets/css/motion.css` — отдельным слоем поверх вёрстки
прототипа, чтобы `tokens.css` и `landing.css` оставались нетронутыми.

| Что | Где | Зачем |
|---|---|---|
| Наезд на кадр hero + точки-индикаторы | `motion.css`, `HeroSection` | видно, сколько кадр ещё провисит; на hover пауза |
| Выезд строк заголовка из-под маски | `motion.css` | единственная «постановочная» анимация на загрузке |
| Появление карточек при скролле | директива `v-reveal` | стаггер внутри списка, у каждой секции свой характер |
| Липкая панель | `StickyBar` | навигация, телефон и поиск под рукой после hero |
| Переезд поиска в панель | `.stickybar-search` | строка прилетает снизу — оттуда, где осталась в hero; задержка 120 мс, чтобы панель успела доехать |
| Ховеры карточек, кнопок, ссылок | `motion.css` | отклик на действие |
| Полка с маскотом | `.shelf` + `Mascot` | выделяет главный ряд, чтобы страница не читалась простынёй |
| Подъезд автобуса и вращение колёс | `v-reveal="'bus'"` + `BusFrame` | блок «Почему выбирают нас» — автобус подъезжает слева, дальше колёса докручиваются от прокрутки |

Правила:

- Кривые только затухающие (`--e-quart` / `--e-quint` / `--e-expo`), без пружин.
- Длительности: 120 мс отклик, 220 мс смена состояния, 420 мс перемещение, 620 мс появление.
- `v-reveal` навешивает классы **только в браузере** — серверная разметка всегда видима,
  поэтому «пустая секция» при отключённом JS невозможна (проверяется `curl | grep rv-pre`).
- Блок `prefers-reduced-motion` в конце `motion.css` гасит всё: анимации, переходы
  и плавный скролл по якорям. Маскот статичен по умолчанию.

### Маскот

Снежный барс (ирбис). Персонаж светлый и висит над белым фоном, поэтому его силуэт обведён тёмным контуром. Компонент `Mascot` рисует встроенный
вектор, пока в Directus не залита нарисованная версия (`landing.mascot_image`, PNG
с прозрачным фоном, ширина от 600px). Промпт и требования — в [docs/IMAGES.md](docs/IMAGES.md).

### Скругления

Три уровня, дальше не плодим:

- `--main-r` (44/28) — полотна во всю ширину: hero, лента отзывов, полотно страницы.
- `--r-block` (28/22) — блоки внутри колонки: промо, полка, карточка заявки, панель преимуществ.
- `--r-card` (20) — карточки и их фотографии.

Отдельно `--r-pill` для кнопок и пилюль: это форма, а не скругление блока.

### Маскот

Барс живёт в двух местах: анфас выглядывает из-за полки «Популярные туры»
(`landing.mascot_image`, пустое поле — рисуется векторная заглушка) и в полный
рост сидит на чемодане слева, на границе лаймового полотна заявки и футера
(`landing.mascot_full_image`, пустое поле — картинка просто не рисуется).
Стоит НА линии, а не разрезан ею: в тёмное уходят только колёса чемодана.
Позиция привязана к колонке контента (`calc(50% - 470px)`), а не к краю
экрана, иначе на широком мониторе он уезжал бы в угол.

Клякса `public/ink-splash.svg` (белая с низкой непрозрачностью) лежит фоном на
лаймовых плашках — полке «Популярные туры» и полотне заявки. Поверх лайма читается
как более светлый оттенок того же цвета. Именно фоном, а не элементом: так она сама
обрезается скруглением блока и не мешает маскоту вылезать за верхний край.

### Доводка вёрстки

`app/assets/css/refine.css` — правки дизайна поверх прототипа, отдельным файлом,
чтобы `landing.css` оставался тем, что отдал дизайн, и любую правку можно было откатить:

- Заголовки секций крупнее, под ними больше воздуха.
- Направления — квадратные плитки. Вертикальные 4:5 занимали больше экрана, чем весь
  блок туров, хотя направление это навигация, а не витрина.
- Ленты карточек идут строго по колонке контента: в прототипе они вылезали за неё
  и справа торчал обрезанный край следующей карточки.
- Отзывы — карточки на светлой подложке. В прототипе они были белыми на белой секции,
  то есть невидимыми.
- Отзывы — цветное полотно со скруглением внутри колонки, как промо и заявка,
  заголовок по центру, карточки белые. В прототипе они были белыми на белом.
- «Почему выбирают нас» — на широком экране блок нарисован каркасом автобуса
  (компонент `BusFrame`), три колонки лежат в его окнах. Каркас перерисован
  примитивами по обмеру присланного PNG: кузов и рамка окон — скруглённые
  прямоугольники, арки и колёса — окружности, спицы — восемь лучей через 45°.
  Растр давал грязную кайму на краях линий и мылил на ретине, вектор — нет.
  Тёмная обводка вокруг линий, которая была в исходном PNG, снята намеренно:
  чистая лаймовая линия читается легче и не спорит с текстом в окнах.
  Разметка встроена, а не подключена картинкой, потому что колёса крутятся.
  Проценты положения окон в `refine.css` — проёмы в координатах viewBox,
  менять их надо парой. Каркас лежит в разметке последним: колонки
  раскладываются по окнам через `nth-child`. Ниже 1081px каркас отключается и остаётся тёмное полотно
  с колонками через волосяную линию.
- Страницу завершает форма заявки (`LeadSection`): слева обращение и контакты,
  справа белая карточка с формой — вопрос, имя с телефоном в строку, почта,
  кнопка. Ссылка на политику берётся из юридического меню футера, отдельного
  поля под неё нет. Блок подписки убран.
- Полотно заявки идёт во всю ширину, контент остаётся в колонке. Стык с белой
  страницей сделан обратной ступенькой: белое полотно заканчивается полосой со
  скруглением вниз (`.lead-sec::before`), поэтому по краям лайм поднимается, а
  в середине опускается белое. Низ полотна срезает скругление самой `.lp-main`,
  дальше футер — низ страницы читается как один спуск белое → лайм → тёмное.
- Бейджи-билеты: у длительности тура две половинки складываются как пазл —
  в правом боку левой паз, на левом боку правой шип, — но не срастаются:
  между ними остаётся просвет в разницу радиусов. Шип не может выйти за
  границы своего элемента, поэтому место под него заложено в padding, а сама
  половинка наезжает отрицательным полем ровно на его ширину. Форма одна на
  все билеты (`.ticket`): выемки маской, высота 26px; одиночная длительность
  тоже билет, иначе она осталась бы обычной пилюлей. У правой половинки маска
  трёхслойная (тело + шип + выемка), и там только стандартный `mask-composite`:
  вместе с `-webkit-mask-composite` Chrome сбрасывает маску целиком.
- В шапке сердце избранного залито красным, как на bogema.ru, а вход в кабинет
  подписан словами (`.hd-lk`): иконка человечка без подписи читается как
  «профиль», а не как вход. Ниже 900px кнопка прячется — там бургер.
- Меню шапки — дерево: у `menu_items` есть `parent`, и пункт с детьми сам
  превращается в выпадающий список. Вёрстка не знает про конкретные разделы,
  редактор в Directus сам решает, что раскрывается. Исключение одно:
  «Направления» тянут список из своей коллекции (пункт ищется по подписи
  `/направлен/i`) — вести те же регионы ещё и в меню значит держать два списка,
  которые разъедутся. Список направлений идёт в две колонки, остальным разделам
  хватает одной. В липкой панели и в бургере берётся только верхний уровень
  и подпункты соответственно.
- Под витриной из восьми направлений лежит строка билетов с остальными
  (`.dest-more`): плиток на все не напасёшься, а страницы надо куда-то деть —
  и для человека, и для поисковика.
- В строке шапки четыре пункта: Туры, Направления, Туристам, Акции. Виды туров
  и заграница — тоже туры, поэтому живут внутри первого списка: шесть пилюль
  подряд читались как свалка, а в липкой панели ломались на две строки.
  Ниже 1160px подписи поджимаются, ниже 1140px исчезает строка поиска в панели,
  ниже 1080px навигация уходит под бургер.
- У ленты отзывов своя шапка: билет с оценкой над заголовком (`landing.reviews_badge`)
  и короткое описание под ним (`landing.reviews_subtitle`). Билет — тот же элемент,
  что у длительности тура, поэтому оценка читается как часть системы, а не как
  наклейка; описание держим узким, строка во всю ширину полотна читается тяжело.
- Промо-баннер — полоса, а не блок в треть экрана. Правый край плашки задан
  кривой: SVG лежит в маске отдельным слоем шириной 130px у правого края,
  остальное закрывает сплошной прямоугольник — так форма не растягивается
  вместе с плашкой. Кадр занимает правую зону в 56%: растянутый на всю полосу,
  он обрезался по высоте до четверти. Кнопка лежит на фотографии, с тенью,
  на наведение только чуть светлеет. На узком экране кривая снимается, но
  вместе с ней надо сбрасывать `mask-size` и `mask-position`, иначе от
  десктопной формы остаётся слой в 130px и плашка схлопывается в угол.
- Строка навигации с выпадающими списками — общий компонент `NavMenu`: и шапка
  над кадром, и липкая панель показывают одинаковое дерево. Раньше панель
  давала плоские ссылки, и разделы с подпунктами из неё было не достать.
- Заголовки hero и промо умеют знаки внутри строки: `{mountains}`, `{route}`,
  `{loop}`, `{paw}` в тексте превращаются в иконки (`TitleIcon`, разбор —
  `utils/titleParts.ts`). Место знака задаёт редактор в Directus, вёрстку
  для этого править не нужно.
- Отзывы — мазок `public/arc-stroke.svg` у правого края полотна: та же кисть, что
  и клякса, но перекрашенная в насыщенный лайм по светлому фону полотна. Уходит
  за край и обрезается скруглением, поэтому читается как росчерк сквозь блок.

## Расписание выездов

Один выезд = одна дата тура (`departures`): тур, дата выезда и возвращения,
город отправления (`departure_cities`), свободные места и цена этой даты.
Пустая цена — берётся `price_from` тура, пустые места — счётчик не рисуется.

На выездах держится всё, что связано с датами:

- «Ближайшие туры» на главной — экскурсии и туры вперемешку, отсортированные
  по ближайшей дате (`nearestFirst` в `utils/departures.ts`). Туры без
  расписания уходят в конец: ставить их первыми в «ближайших» — обман.
- Строка дат на карточке — ближайшая дата плюс «ещё N дат».
- Дальше на них лягут фильтр по городу выезда и расписание на странице тура.

С сервера тянутся только будущие выезды: прошлые карточкам не нужны, а архив
расписания растёт быстро.

## Страницы

| Адрес | Что это |
|---|---|
| `/` | Главная (layout `default`: шапка над кадром + липкая панель) |
| `/tours` | Каталог всего ассортимента с фильтрами (layout `page`) |

Внутренние страницы живут на layout `page`: шапка не висит над фотографией,
а стоит на белом (`.lp-header.is-solid`), липкая панель не нужна.

Каталог берёт данные из `useCatalog()` — отдельно от `useLanding()`, потому
что там выборка ограничена `featured`, и тянуть полный список на каждую
страницу незачем. Фильтрация считается на клиенте (`utils/catalogFilter.ts`):
пока туров сотни, это дешевле и отзывчивее, чем ходить в Directus на каждое
движение фильтра; когда список вырастет, туда встанет серверный запрос —
интерфейс останется прежним.

Фильтры: поиск по названию, месяц выезда, направление, город выезда,
длительность, цена и сортировка. Месяцы показываются только те, в которых
реально есть выезды — вести человека в пустой февраль незачем. Поиск не дёргает
адрес на каждую букву, ждёт паузы в наборе.

На экранах уже 900px панель схлопывается в кнопку «Фильтры» со счётчиком, а сами
фильтры приезжают шторкой снизу и закрываются по «Показать N». Развёрнутая
панель занимала там пол-экрана, и до карточек надо было доскроллить — ровно та
жалоба, что была на старом сайте.

Состояние фильтров лежит в адресе (`?poisk=&mesyac=&napravlenie=&gorod=&dlitelnost=&s=&po=&cena=&sort=`):
подборку можно отправить ссылкой, а «назад» возвращает предыдущий набор.
Фильтры по городу и датам — это фильтр по расписанию: тур попадает в выдачу,
если у него есть хотя бы один подходящий выезд, и на карточке показывается
именно он.

## Горящие туры

Тур считается горящим, если в админке заполнена `old_price` и она больше
обычной цены. Отдельного флага нет: одно поле вместо двух, и невозможно
поставить «горящий» без самой скидки. Скидка считается сама и показывается
дважды — красным бейджем на фото и зачёркнутой ценой рядом с текущей.

Секция `#hot` стоит на главной сразу после промо: за скидками приходят
целенаправленно, и прятать их под две витрины смысла нет.

## Рабочий цикл «натянуть вёрстку»

1. Секция лендинга = компонент в `app/components/sections/`, карточка = `app/components/ui/`.
2. Нужно новое поле/коллекция → добавить в админке Directus **или** в `seed-schema.mjs`,
   затем `pnpm directus:snapshot` и закоммитить `directus/schema/snapshot.yaml`.
3. Продублировать поле в `app/types/schema.ts` и в моках `app/data/mock.ts`.
4. Достать в `useLanding.ts` (если новая коллекция) и прокинуть в секцию через props.

Стили: `tokens.css` (бренд, кнопки, инпуты) и `landing.css` перенесены из прототипа как есть,
только `<image-slot>` заменён на `.slot` / `.slot-empty`. Свои дополнения — в `main.css`
или scoped-стили компонентов.

## Переменные окружения

Compose (`.env` в корне) — см. `.env.example`: порт, `KEY`/`SECRET`, админ, Postgres, `FRONTEND_ORIGIN`.

Nuxt (`frontend/.env`) — см. `frontend/.env.example`:

- `NUXT_PUBLIC_DIRECTUS_URL` — публичный адрес Directus (для картинок и клиента)
- `NUXT_DIRECTUS_INTERNAL_URL` — адрес внутри docker-сети (только SSR)
- `NUXT_DIRECTUS_TOKEN` — статический токен для записи заявок (необязательно)
- `NUXT_PUBLIC_USE_MOCK` — верстать на моках
- `NUXT_PUBLIC_SITE_URL` — canonical / og:url
- `NUXT_PUBLIC_TELETYPE_ID` — ключ чата Teletype. Пусто (по умолчанию) — виджет
  не подключается, поэтому в деве и на превью чат не мешает. Скрипт грузится
  не сразу, а когда браузер освободился после отрисовки: виджет тянет свой
  бандл со шрифтами и аватарами, и на первом экране это лишний вес.

## Деплой

Фронт собирается в образ из корня репо: `docker build -f frontend/Dockerfile -t bogema-landing .`
и запускается как node-сервер на :3000. Directus — тот же `docker-compose.yml`
(с нормальными секретами и `PUBLIC_URL`). Оба сервиса встают за Traefik из
`bogema-infra` так же, как `app`/`minio`: свой домен на лендинг, свой на CMS.
Для прода включить `routeRules['/'].swr` в `nuxt.config.ts`, чтобы не дёргать CMS на каждый запрос.

Формы (`/api/subscribe`, `/api/lead`) пишут в Directus с сервера Nuxt — токен в браузер не попадает.
